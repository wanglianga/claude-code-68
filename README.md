# 童趣安 · 城市儿童游乐场会员入园与安全事故处置系统

## 原始需求

> 设计城市儿童游乐场会员入园与安全事故处置页面，可使用 React、TypeScript 和 TanStack Query。家长购买会员卡或次卡后，页面记录儿童年龄、身高、过敏史、紧急联系人、可陪同监护人、禁玩项目和剩余权益。入园时，前台核验会员、儿童身份、陪同人授权和当天限流；页面根据场内人数、项目身高限制、设备开放状态和生日活动安排推荐游玩顺序。运营人员巡场时记录滑梯、蹦床、攀爬网、海洋球池、卫生间和休息区状态。若儿童摔倒、被其他孩子推搡、设备临停、家长找不到孩子、会员卡争议或家长要求退课，页面要把前台、巡场、店长、医疗点和家长沟通放到同一事件。事故处理结束后，现场照片、监控时间段、家长签字、赔付方案、设备复检和会员权益调整进入档案，店长可以按项目、时段和人员复盘安全隐患。页面还要把手环定位、监控调阅、急救箱使用、消毒记录、会员补偿和员工交接合在同一条事件线里。对于多人共同参与的生日会或托管班，页面需要标明每个儿童对应的监护人和活动负责人，防止事故沟通时找不到真正授权人。

## 功能总览

| 模块 | 说明 |
| --- | --- |
| 运营概览 | 在场人数/当日限流、项目开放状态与实时人数、进行中事件、今日生日会/托管班、手环扫码定位模拟、最近巡场 |
| 会员与儿童档案 | 会员卡/次卡、剩余次数与剩余权益；儿童年龄、身高、过敏史、禁玩项目；紧急联系人与可陪同监护人（授权标记） |
| 入园核验 | 五步核验链：会员状态 → 儿童身份 → 陪同人授权 → 当日限流 → 手环分配；次卡自动扣减；未授权陪同人/次卡不足/超限流均被拦截 |
| 游玩推荐 | 按场内各项目实时人数（手环定位统计）、身高限制、设备开放状态、生日活动冲突，输出推荐游玩顺序与不可玩原因 |
| 巡场记录 | 滑梯/蹦床/攀爬网/海洋球池/卫生间/休息区状态打卡，可一键同步设备开放状态（异常→维护中） |
| 设备临停分流 | 临停自动生成处理单：受影响儿童快照、排队人数、可替代项目（按身高/禁玩适配）、会员补偿方式；前台解释后排队号分流+补券+复检状态联动更新，手环无法扫码进入已停用项目；恢复开放强制「检修照片+负责人确认」，补券不能替代安全复检；生日会延误/课程补时/家长投诉合并到同一处理单 |
| 事件中心 | 六类事件（摔倒/推搡/设备临停/走失/卡争议/退课）统一上报；前台、巡场、店长、医疗点、家长沟通在同一事件线协同 |
| 受伤赔付协商 | 儿童擦伤/扭伤后收集**项目、动作、陪同人位置、急救处理、家长诉求**；店长三选一（**医药费报销 / 课时补偿 / 继续观察**），决策即同步**会员卡权益**与事故复盘议程；协商结束自动生成**家长确认**与**员工复盘任务**；复盘会标记**项目动线、员工站位、家长视线盲区**，同类项目在巡场核验完成前**限制开放（不按原规则开放）**，标记转为下一次巡场待办，全部核验后店长解除 |
| 走失快速定位 | 家长报告孩子不见后自动生成查找任务（最后入场项目、手环编号、监控点位、巡场人员分派）；查找期间自动冻结该儿童手环出园，前台与门口安保看到同一风险提示；巡场登记发现地点/陪同人/孩子状态/是否安抚后事件才能关闭；曾被其他家长带离时记录对方监护人并下发巡场提醒 |
| 统一事件线 | 手环定位、监控调阅、急救箱使用、消毒记录、会员补偿、员工交接、家长沟通等 12 类条目汇入同一时间线 |
| 事件归档 | 仅「已解决」事件可归档；按事件类型校验适用资料——适用项必须提供真实资料（不能用结论替代），不适用项保存明确结论（可手填或自动生成）；现场照片、监控时间段、家长签字、赔付方案、设备复检、会员权益调整（补偿次数直接写入会员卡）进入安全档案 |
| 安全复盘 | 店长按项目、时段、人员筛选事件，查看类型/项目/时段分布与人员参与度、档案明细 |
| 生日会/托管班 | 每个儿童登记对应监护人（仅可选已授权陪同人）与活动负责人，事件详情页直接展示同班儿童授权人 |
| 时间口径 | 全场统一按 Asia/Shanghai 展示与计算（活动时间、今日范围、时段统计、datetime 输入解析） |

## 技术栈与架构

- **前端**：React 18 + TypeScript + TanStack Query v5 + React Router v6（Vite 构建，手写设计系统 CSS）
- **服务端**：Node.js 20 + Express 4 + better-sqlite3（WAL 模式，首次启动自动建表+灌入演示数据）
- **部署**：多阶段 Dockerfile（前端构建 → 服务端依赖 → 非 root 运行时 + HEALTHCHECK），docker compose 单服务一键启动，SQLite 数据持久化到 named volume

```
workspace/
├── Dockerfile              # 多阶段：webbuild → serverdeps → runtime(非 root + HEALTHCHECK)
├── docker-compose.yml      # 仅发布应用端口 ${CC_PUBLISH_PORT}:8080
├── .env.example
├── server/                 # Express + SQLite
│   └── src/{index.js,db.js}# API 路由 / schema+seed
└── web/                    # React + TS + TanStack Query
    └── src/{pages,api.ts,auth.tsx,...}
```

## 快速开始（Docker 一键部署）

前置：已安装 Docker 与 docker compose 插件。

```bash
# 1. 配置环境变量（可选，默认值即可运行）
cp .env.example .env

# 2. 构建并启动
docker compose up -d --build

# 3. 查看实际映射端口（宿主机端口由 CC_PUBLISH_PORT 决定）
docker compose port app 8080
# 浏览器访问 http://localhost:<映射端口>

# 4. 健康检查
curl http://localhost:<映射端口>/api/health

# 5. 停止并释放资源
docker compose down
```

> 验证方式说明：本系统以「宿主机执行 `docker compose up -d` 后容器健康、关键业务流可在浏览器/接口走通」为验证通过标准；应用容器内非 root 运行，自带 HEALTHCHECK，`docker compose ps` 可见 `(healthy)`。

## 关键业务流自测路径

1. **入园核验**：前台登录 → 入园核验 → 搜「吴敏」（次卡 0 次，被拦截）；搜「张莉」→ 选张小雪 → 奶奶王秀兰不可选（未授权）→ 选父亲王建国 → 自动分配手环 → 放行。
2. **游玩推荐**：游玩推荐 → 选张小雨 → 攀爬网因「禁玩」被拦截、蹦床因「维护中」被拦截，海洋球池提示 15:00 生日会错峰。
3. **事件处置**：事件中心打开 EV-…-0001 → 追加「家长沟通/手环定位/监控调阅」等条目 → 店长登录 → 先「标记解决」→ 再归档（适用资料缺失会被 400 拦截并提示，可补资料或填明确结论；不适用项自动生成结论）→ 会员 M1001 权益自动调整。
4. **复盘**：店长 → 安全复盘 → 按项目「海洋球池」或人员「李强」筛选，查看分布与档案明细。
5. **走失定位**：任意角色上报「走失寻人」事件（关联在场儿童）→ 自动生成查找任务并冻结该儿童手环出园（离场返回 423）→ 巡场登记发现地点/陪同人/孩子状态/是否安抚（曾被其他家长带离须记录对方监护人）→ 店长/医疗点方可关闭事件，出园冻结随之解除。
6. **临停分流**：设备临停分流 → 打开 ST-…-0002（蹦床）→ 前台将排队号 B-01/B-02 分流到可替代项目、发放「次卡补偿」补券（自动写入会员次数）→ 巡场提交检修照片与复检结果 → 店长「负责人确认」→ 恢复开放（缺照片或确认会被 400 拦截）；期间可追加课程补时/家长投诉子项并办结。
7. **受伤赔付协商（主流程）**：店长登录 → 受伤赔付协商 → 打开 IC-…-0001（张小雨擦伤，信息已收集）→ 在「医药费报销 / 课时补偿 / 继续观察」中三选一（如课时补偿 2 节，会员卡立即加次并留痕）→ 前台在协商单「家长确认」登记签字（未确认前事件归档会被 400 拦截）→ 店长开复盘会，分别添加**项目动线 / 员工站位 / 家长视线盲区**标记（三类缺一不能结束复盘）→ 结束复盘：项目自动「限制开放」并生成复盘巡场待办，手环扫码、游玩推荐、临停分流均无法再进入该项目 → 巡场登录在「巡场记录 → 复盘巡场待办」逐条核验 → 店长确认解除限制开放，项目恢复原规则；随后事件可归档，赔付方案与家长签字自动带入档案。
8. **复盘汇总**：店长 → 安全复盘，可查看受伤赔付协商汇总（报销金额/课时合计/方案分布）与「动线·站位·盲区」标记明细表，作为下一次巡场依据。
